# v3：可选的本机声音测量

日期：2026-11-01。状态：本地原型，单模态（麦克风音量/停顿）。

## 1. 目标

在 v0/v1 的躯体与意象捕获之外，增加一个**明确同意、完全本地**的信号摘要：

- 8 秒麦克风音量与停顿；
- 只保存摘要（RMS 均值、P95、停顿比例、采样率、时长）；
- 不保存原始音频；
- 不上传。

这不是 LSM，也不是生理传感器；它只是一个可验证的“信号摘要 + 自报”接口。

## 2. 交互

- v0 表单底部增加「可选：本机声音测量」。
- 必须主动勾选「允许本机麦克风测量」。
- 按「测量 8 秒」后才请求麦克风；5 秒内无法启用则显示错误，不影响仅记录身体与意象。
- 测量结束后显示音量均值与停顿比例；摘要随母题保存。
- 母题日记显示「含本机声音摘要」。
- 可关闭保存开关；不保存时摘要不写入 localStorage。

## 3. 数据

`VoiceTrace`：

```ts
{ version:'voice-v1', durationSec, sampleCount, rmsMean, rmsP95, pauseRatio, sampleRate }
```

`MotifSignals`：

```ts
{ consent: SignalConsent, voice?: VoiceTrace }
```

`SignalConsent` 固定 `localOnly: true`、`purpose: 'local_research'`。

## 4. 不声称什么

- 不是心理生理测量、不是诊断、不是情绪识别。
- 不保存可还原的原始音频。
- 不把音量/停顿解释成焦虑、创伤或关系状态。
- 没有传感器、没有 HRV、没有皮肤电、没有跨用户数据。

## 5. 安全与隐私

- 麦克风只在点击后开启；失败/超时有明确提示。
- 默认不请求权限。
- 保存是可选项；全部本地。
- 清除浏览器数据即丢失；导出是用户主动行为。
- 若用户不想测量，v0/v1 流程完全不受影响。

## 6. 局限性

- 当前环境（headless Chrome）无法启用麦克风，只验证了失败路径；真实麦克风路径仍需在手机/桌面浏览器验收。
- 音量/停顿受设备、距离、环境噪声影响，不能当作稳定生理指标。
- 还没有与身体自报、意象选择做跨模态对齐研究。

## 7. 下一步

- 在真实设备上验证麦克风路径与摘要稳定性。
- 再考虑可选的呼吸/HRV 传感器；仍保持明确同意、本地优先、可删除。
- LSM 仍只是方向，不是已训练模型。
